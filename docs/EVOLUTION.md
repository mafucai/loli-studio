> 定位：六层体系**第六层（演化层）**。把真实缺陷和门禁经验写回系统。
> 更新方式：**持续写**，每次缺陷修复后补一条。不是一次写完的文档。
> 与 `PROGRESS.md` 的分工：`PROGRESS.md` 说「做到哪了」，本文件说「错过什么、学到了什么」。

## 二、缺陷记录

### D1 — color 单值改数组后，5 处使用点漏改

| 项 | 内容 |
|---|---|
| **现象** | 出图/搜索词的 prompt 里出现 `"雾霾蓝,奶油白"`（数组被隐式转成逗号串），或 `"undefined"` |
| **发现方式** | 写批 C 时顺手 grep，**不是被断言抓到的** |
| **根因** | 批 B 把 `words.color` 从字符串改成数组，只改了**定义处**（`factory.js` 的 `designWords`）和**显式使用处**，漏了 5 处隐式字符串拼接：`actions.js`×3、`settings.js`×1、`ai.js`×1 |
| **为什么断言没抓到** | 当时的断言只测「`toColors` 函数本身对不对」，**没测「所有调用点是否都用了它」** |
| **应对** | ① 修复 5 处；② 新增「脏 prompt 检测」实测（不许出现 `undefined`、不许出现逗号串、多色须用顿号） |
| **规则更新** | **R1：改数据结构时，grep 全部使用点，不只看定义处** |
| **是否已进断言** | ✅ `backcompat-test.js` F 组（8 项） |
| **遗留** | 我尝试过用**源码正则**做「裸用法扫描」，误报 4 次后放弃——改用**真实数据实测**。教训：能用实测就不用正则 |

### D2 — vPlan 用了未导出的 screen()

| 项 | 内容 |
|---|---|
| **现象** | 企划页运行时抛 `ReferenceError: screen is not defined`，页面白屏 |
| **发现方式** | **`full-logic-test.js` 跑出来的**（不是 `ui-regression.js`） |
| **根因** | `screen()` 是 `render.js` 的**内部函数**，`render-extra.js` 直接裸引用。UI 断言是**静态文本匹配**，看不到运行时报错 |
| **应对** | ① `render.js` 导出 `R.screen`；② `render-extra.js` 改为 `R.screen(...)` |
| **规则更新** | **R2：关键路径必须真跑，静态断言只作辅助**；**R3：拆文件时内部函数要么导出、要么显式传参** |
| **是否已进断言** | ✅ `error-assistant-test.js` 走真实代码路径（26 项）；⚠️ 但**R3 本身还没有断言**（见「未完成」） |
| **元结论** | **这是一条方法论，不是一条普通缺陷**：静态断言（grep 源码）和动态验证（真跑代码）是两种东西，**前者抓不到运行时报错**。本项目的 `ui-regression.js` 属于前者，`full-logic-test.js` 属于后者，两者不可互相替代 |

### D3 — dom-test.js 从建立那天起就不可能通过

| 项 | 内容 |
|---|---|
| **现象** | 末尾「点击三个页签」3 项断言永远失败 |
| **根因** | 该脚本手写的 DOM 桩里，`parseHTML` **只建标签节点、不解析文本节点** → `span>设计</span>` 里的中文从未写入 `_text` → `tabs[i].textContent` 恒为空 → `find(...includes(label))` 永远找不到 |
| **附加发现** | 该脚本的加载列表**漏了 `render-extra.js` 和 `settings.js`**，与 `index.html` 不同步 |
| **它是回归测试吗** | **不是**。`PROGRESS.md` 的 260 项里从未包含它，CI 也没接 |
| **应对** | ① 补上加载列表；② **在文件头写明报废原因，不假装修好**；③ 保留它唯一还有用的功能——检查加载列表是否与 `index.html` 同步 |
| **规则更新** | **R6：不能用的脚本要么修、要么写清报废原因，不许假装修好** |
| **是否已进断言** | ✅ 报废原因已写入文件头（可 grep 验证） |

### D4 — actions.js 涨到 453 行，破了 400 铁律

| 项 | 内容 |
|---|---|
| **现象** | `ui-regression.js` 第 4 项断言失败：`actions.js 行数 453 ≤ 400` |
| **根因** | 图透 6 个动作（71 行）塞进一个已经 380 行的文件 |
| **应对** | 拆出 `vote-actions.js`（88 行），用 `Actions.registerVote(ACT, {...})` 注入，**不产生两套事实源** |
| **规则更新** | **R5：单文件逼近 400 行时主动拆，不要等超了再拆** |
| **是否已进断言** | ✅ 行数断言（`prototype/js/core/*.js` 全部 ≤400） |

### D5 — 「共 9 步」硬编码在 9 处

| 项 | 内容 |
|---|---|
| **现象** | 加入企划、图透两步后，9 个页面的副标题仍显示「第 N 步，共 9 步」，实际已是 11 步 |
| **根因** | 步骤文案写死成字符串，与 `Router.STEPS` 脱钩 |
| **应对** | 新增 `stepLabel(id)`，从 `Router.STEPS` 动态取 `n` 和 `length` |
| **规则更新** | **R4：文案里的数字一律动态取，不硬编码** |
| **是否已进断言** | ✅ 17i（`render.js` 不含「共 9 步」）+ 17j（`stepLabel` 存在） |

### D6 — 门禁此前从未自动运行

| 项 | 内容 |
|---|---|
| **现象** | `apk.yml` 里**没有任何测试步骤**，裸构建就出包 |
| **根因** | 断言只在文档里要求「提交前记得跑」，**未接 CI** |
| **后果** | 260 项「全绿」只是某次手动跑的结论，**CI 里不存在**；一旦只推送不本地跑，坏包直接进 Release |
| **应对** | `apk.yml` 在 `Set up Java` **之前**插入 `Set up Node 20` + 7 个断言脚本，**不过就不出包** |
| **规则更新** | **R7：门禁必须自动运行（接 CI），否则等于没有** |
| **是否已进断言** | ✅ 接入 `apk.yml`（YAML 已校验） |

## 四、门禁效果评估

> 六层体系要求「漏检、误报和门禁效果评估」。

| 门禁 | 抓到过什么 | 漏过什么 |
|---|---|---|
| `ui-regression.js`（161 项，静态） | D4 行数超限、D5 文案硬编码、data-act 未处理、加载顺序错误 | **D2 运行时错误（静态匹配看不到）**、D1 隐式类型错误 |
| `full-logic-test.js`（74 项，动态） | **D2**（真实抛错） | 需手写桩，覆盖面有限 |
| `backcompat-test.js`（35 项，实测） | **D1 类**（脏数据混进 prompt） | 同上 |
| `error-assistant-test.js`（26 项，动态） | 报错助手链路完整性 | 同上 |
| `dom-test.js` | **D3**（发现它自己报废） | 它不是门禁 |

**结论**：**静态断言抓「结构」，动态实测抓「行为」，两者缺一不可。** 本项目两类都有，但动态类偏少（74+35+26 = 135 项 vs 静态 161 项），后续应补更多实测。
