### D1 — color 单值改数组后，5 处使用点漏改

| 项 | 内容 |
|---|---|
| **现象** | 出图/搜索词的 prompt 里出现 `"雾霾蓝,奶油白"`（数组被隐式转成逗号串），或 `"undefined"` |

| **应对** | ① 修复 5 处；② 新增「脏 prompt 检测」实测（不许出现 `undefined`、不许出现逗号串、多色须用顿号） |

| **遗留** | 我尝试过用**源码正则**做「裸用法扫描」，误报 4 次后放弃——改用**真实数据实测**。教训：能用实测就不用正则 |

### D2 — vPlan 用了未导出的 screen()

| 项 | 内容 |
|---|---|
| **现象** | 企划页运行时抛 `ReferenceError: screen is not defined`，页面白屏 |
| **发现方式** | **`full-logic-test.js` 跑出来的**（不是 `ui-regression.js`） |
| **根因** | `screen()` 是 `render.js` 的**内部函数**，`render-extra.js` 直接裸引用。UI 断言是**静态文本匹配**，看不到运行时报错 |
| **应对** | ① `render.js` 导出 `R.screen`；② `render-extra.js` 改为 `R.screen(...)` |
| **规则更新** | **R2：关键路径必须真跑，静态断言只作辅助**；**R3：拆文件时内部函数要么导出、要么显式传参** |
| **是否已进断言** | ✅ `error-assistant-test.js` 走真实代码路径（26 项）；⚠️ 但**R3 本身还没有断言**（见「未完成」） |
| **元结论** | **这是一条方法论，不是一条普通缺陷**：静态断言（grep 源码）和动态验证（真跑代码）是两种东西，**前者抓不到运行时报错**。本项目的 `ui-regression.js` 属于前者，`full-logic-test.js` 属于后者，两者不可互相替代 |

### D7 — 脚本硬编码绝对路径，导致 CI 失败而本地全绿

| 项 | 内容 |
|---|---|
| **现象** | push 后 CI 在 `Regression gate` 失败（exit 1，job 仅 9s）；但本地 node 18 / node 20、干净克隆、bash + `set -uo pipefail` **全部复刻都无法重现**（7 个脚本退出码全 0） |
| **真因** | `backcompat-test.js` / `error-assistant-test.js` / `dom-test.js` 把 `ROOT` 写成开发环境绝对路径 `/workspace/apps/loli-studio/prototype`。CI 里项目在 `/home/runner/work/loli-studio/loli-studio` → `ENOENT: no such file or directory` |
| **为什么本地永远复现不出** | **本地 `pwd` 恰好等于那个硬编码路径**，所以能过。前面 5 个脚本用 `path.join(__dirname, "..")` 所以正常，只有新写的 3 个写死了 |
| **定位过程** | ① 加诊断输出（打印 `node -v` / `pwd` / 每个脚本退出码）→ ② **`gh run view --log-failed` 拿到真实报错** → 一眼看到 `ENOENT` |
| **应对** | `ROOT` 改为 `path.join(__dirname, "..", "prototype")`；在 `/tmp/ci-sim4`（**不同工作目录**）+ node 20 下验证 7 个脚本全过 |
| **规则更新** | **R8：脚本禁止硬编码绝对路径**；**R9：CI 失败先取日志，不要靠本地复刻猜** |
| **是否已进断言** | ✅ **已进**（`ui-regression.js` 16b）。已验「故意注入硬编码路径 → 变红，恢复 → 变绿」 |

**过程反思（比缺陷本身更重要）**：

1. **我在本地复刻上绕了 5 轮**（装 node 20 / 干净克隆 / 模拟 bash），方向全错——**本地 pwd 就是那个硬编码路径，永远复现不出来**。
2. **正确的第一步是取 CI 日志**，而 `RISK_CHECKLIST.md` 第 35 条早就写了：**「Actions 失败时保存日志、截图和命令输出」**。主人提醒了**两次**「有流程文档你不用那么费劲查看一下」，我才去查。
3. **结论**：**失败发生在哪个环境，就去哪个环境取证据。** 跨环境问题靠本地复刻是低效且可能永远无效的。

## 四、门禁效果评估

> 六层体系要求「漏检、误报和门禁效果评估」。

| 门禁 | 抓到过什么 | 漏过什么 |
|---|---|---|
| `ui-regression.js`（162 项，静态） | D4 行数超限、D5 文案硬编码、data-act 未处理、加载顺序错误 | **D2 运行时错误（静态匹配看不到）**、D1 隐式类型错误 |
| `full-logic-test.js`（74 项，动态） | **D2**（真实抛错） | 需手写桩，覆盖面有限 |
| `backcompat-test.js`（35 项，实测） | **D1 类**（脏数据混进 prompt） | 同上 |
| `error-assistant-test.js`（26 项，动态） | 报错助手链路完整性 | 同上 |
| `dom-test.js` | **D3**（发现它自己报废） | 它不是门禁 |

**结论**：**静态断言抓「结构」，动态实测抓「行为」，两者缺一不可。** 本项目两类都有，但动态类偏少（74+35+26 = 135 项 vs 静态 162 项），后续应补更多实测。

**D7 补记——门禁「抓不到跨环境问题」**：

372 项断言**全部通过**的情况下，CI 依然失败。原因是**断言本身有环境依赖缺陷**（硬编码路径）。

| 层次 | 本地 | CI |
|---|---|---|
| 断言逻辑 | ✅ 全过 | ✅ 全过（只要能读到文件） |
| **文件能否读到** | ✅ 恰好命中硬编码路径 | ❌ `ENOENT` |

**结论**：**门禁的「通过」只在其运行环境内有效。** 跨环境问题（路径、换行符、大小写敏感、时区、编码）断言抓不到，**只能靠 CI 真实运行暴露**——这也正是 R7（门禁必须接 CI）比断言本身更重要的原因。

## 批 E3 新增（2026-09）

### D8 — 断言把「会随批次变的数字」写死

**现象**：批 E3 加了 `board` 步骤（第 14 步）和 4 个新脚本（index.html 从 15 涨到 19）后，`ui-regression` 的 6/10a 与 `backcompat` 两条**立即失败**，但产品代码完全正确。

**根因**：断言写成 `stepsCount === 13` / `htmlScripts.length === 15` / `Router.nextId("pre") === ""`。这些数字**每加一批就会变**，属于「把易变值写死」。

**应对**：
- 步数、脚本数改为 **`>= 基线` + 结构性断言**（如「最后一步是 board」「每步都有 id」），不再等值比较。
- `nextId("pre")` 改为断言「`pre` 有下一步 `board`」+「`board` 无下一步」。

**规则更新 → R10（见下）**。

### D9 — 断言比源码更严，反向逼出代码缺陷

**现象**：写断言 `22w` 检查「区分低于触发与高于触发」时，我断言源码里同时存在 `=== "low"` 与 `=== "high"`。结果失败——源码只有 `=== "low"`，`high` 是**隐式 fall-through 默认分支**。

**根因**：代码功能正确（`level()` 返回值对），但**分支意图不显式**：读代码的人无法一眼看出 `high` 是被支持的合法入参，而非「其他一切值都当 high 处理」。

**应对**：把 `high` 补成显式分支，末尾 `return "none"`（方向不明则不下结论）。

**元结论**：**断言偶尔比源码更严，这不是断言写错**。当断言要求「显式表达意图」而源码靠隐式默认时，应改源码而非放宽断言 —— 隐式默认正是 D1 类「脏数据混进逻辑」的温床。

### 规则更新（R10）

> **R10 — 易变值不得写死在断言里**
> 步数、脚本数、条目数、版本号等**每批都会变**的值，断言只能做「不低于基线」或「结构自洽」检查（如首尾项、唯一性、与另一处一致）；等值比较只允许用于**真正不变**的值（阈值常量、枚举成员、字段名）。

**落地断言**：`ui-regression` 6/6b/10a、`backcompat` 「STEPS 不少于 13 步」。

## 批 E4 新增（2026-09）

### D10 — 状态机「定义了但走不到」（断头路）

**现象**：12 项断言全绿、7 个脚本 exit=0 的情况下，主人要求「检查所有功能是否正常」，实测发现
款状态机的后 4 个状态（生产中 / 已发货 / 售后中 / 完结）**在界面上没有任何按钮能推进到**。
文档 §十 第 9 项「大货」实际是**断头路** —— 状态定义了、流转规则也写对了，但**没有入口**。

**根因**：断言只查「结构」（状态机规则是否存在、流转是否合法），
**不查「可达性」（有没有动作能走到这个状态）**。
这类问题在「断言全绿」时完全不暴露 —— 它属于 **结构合规 ≠ 功能可用**。

**应对**：
1. 新增 `scripts/flow-walkthrough.js`，专查两个断言查不到的维度：
   - 视图里每个 `data-act` 是否都有处理函数（防「点了没反应的死按钮」）
   - 每个款状态是否有界面动作能推进到（防「定义了走不到的断头路」）
2. 补 `design-next` / `design-reopen` 动作 + `blockBatch()` 视图。

**元结论**：**断言全绿证明不了功能可用。** 断言的强项是「结构自洽」，弱项恰恰是
「用户能不能走到那儿」。凡是**状态机 / 流程**这类东西，除了查规则，**必须额外查可达性**。

### 规则更新（R11）

> **R11 — 状态机必须查可达性，不能只查规则**
> 定义了状态与流转，不等于用户能走到。任何状态机/流程，都要有一条断言回答：
> **「哪个人机交互能把这个状态推进出来？」** 答案是「没有」的状态，就是断头路，
> 等同于功能缺失。检查方式见 `scripts/flow-walkthrough.js`。

### D11 — 断言全绿，功能却不可达（同 D10 第三次重演）

**现象（主人逐行实测查出，我没查出）**：
1. **步骤图断头路**：E1~E3 做了定样/预售/看板三步视图，`nextBtn` 却没接过去 ——
   用户从成本页**点不到定样**，后面全链条（开团/成团/退款/发货/看板）**一个都进不去**。
2. **`buildBoard` 零调用点**：模型函数有导出、`backcompat` 有 41 项断言实测它，
   但 **App 代码无任何调用点** → 进了看板页也永远显示「还没有可统计的预售数据」。
3. **`confirm()`/`prompt()` 在 APK 静默失效**：`WebChromeClient` 只重写 `onConsoleMessage`，
   WebView 默认对 `onJsConfirm` 返回 false、`onJsPrompt` 返回 null →
   删除设计单/删除接口/录 UV **在真机点了没反应**（浏览器里正常，只有 WebView 壳会踩）。

**根因**：
- 我一直在查「**代码在不在**」（有没有函数、有没有处理函数、断言过不过），
  没查「**用户走不走得到**」（步骤之间有没有路、模型函数有没有人调、运行环境支不支持）。
- 断言测的是**函数行为**，不是**可达性**。可达性是**结构属性**，得单独查。

**规则更新 → R12**：

> **R12 — 「有代码」≠「走得到」：界面可达性 + 运行环境能力必须实测**
>
> 审查功能时必须逐层验证，缺一层就等于没做：
> 1. **步骤图可达**：除入口外每个 step 必须有 `nextBtn`/入口指向（`flow-walkthrough` 已加）
> 2. **动作有按钮**：每个 `data-act` 必须能被用户点到（`dom-contract.js` 已查）
> 3. **模型函数有调用点**：导出的函数必须在 App 里有调用（`buildBoard` 教训）
> 4. **运行环境能力核对**：依赖浏览器/WebView 默认行为的 API（`confirm`/`prompt`/`alert`/
>    `localStorage`/`Notification` 等）**必须打开原生壳源码核对**，不能假设浏览器行为成立。
>
> **一句话：断言只证明「函数对」，不证明「用户到得了」。**

**同轮新发现的既有隐性 bug（此前从未触发，被新断言踩出）**：
- `render-extra.js:58` 裸引用 `nextBtn`（它只是 `render.js` IIFE 的内部函数）。
  真实浏览器靠**全局污染**侥幸能跑 → 一旦被沙箱/严格模式加载即 `ReferenceError`（6 项断言失败）。
  **这正是 R3 的违反**（拆文件须导出或 wrapper），且**潜伏了整整几批没被发现**——
  因为那条渲染路径**从未被触发**。反面印证 R12：**没被走到的代码，等于没写**。
