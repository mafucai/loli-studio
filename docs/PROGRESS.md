### 2.3 报错助手（真机已验）

- 常驻角标（正常 `✓` / 有错红色数字），随时点开

- 双通道：页面红框 + 原生桥 → logcat（`LoliStudio` / `LoliStudio-JS`）
- 捕获阶段抓资源加载失败（IMG/SCRIPT/LINK）

### 2.4 图片出图链路（多轮修复后）

- **b64_json 优先**：一次调用直接拿到图片数据，无二次下载

- 原生桥下载（Java，绕 CORS 与混合来源），超时 15~45 秒封顶
- 进度提示：`正在生成图片…（N 秒 · 尝试 b64/1024x1024）`
- 兼容响应形状：`b64_json` / `url` / `images` / `revisions`

## 四、要做「全套预售流程」意味着什么（必须先说清）

**这不是加几个按钮，是引入半个电商系统，需要新增：**

| 新东西 | 为什么要 |
|---|---|
| **订单模型** | 定金单、尾款单、发货单，各自状态流转 |
| **金额与状态机** | 定金 → 成团/流团 → 尾款 → 发货 → 收货 → 售后 |
| **成团判定逻辑** | 预定量 vs 成团线；达成/未达成两条分支 |
| **用户维度** | 谁付了定金（现在 App 无用户概念） |
| **通知** | 补尾款通知、成团通知 |
| **退款路径** | 流团退定金 |

**且必须明确边界（避免走失败品老路）：**

- **本 App 不收款**。App 只记录「谁付了定金、成团线、尾款状态」，**真实收付款走平台**（或线下）。App 内不接支付、不存卡号。
- **本 App 不自动通知用户**。只生成待通知清单，你自己发。
- **本 App 不代替平台**。开团上架仍在你选的平台做，App 是**计划与记录工具**。

**如果不认同这三条边界，这套就不该做进 App。**
